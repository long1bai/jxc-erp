# jxcERP v2 测试资产

本目录存放自动化测试脚本与测试报告。所有测试都跑在**真实生产库**上（http://127.0.0.1:8080），测试数据统一「【测试】」/「【压测】」前缀，**脚本结束自动全量清理 + 单据序列重同步**，不留脏数据。

## 脚本清单

| 脚本 | 覆盖 | 断言数 | 运行 |
|---|---|---|---|
| `scripts/e2e_test.py` | 全功能回归：基础资料/采购/销售/BOM/生产/库存/报工/财务/报表/系统/AI | 168 项 | `cd /i/yawei-erp-java/scripts && python e2e_test.py` |

## 机制说明

- **数据隔离**：客户/供应商/物料/单据/账户等全部带「【测试】」「【压测】」前缀 + 运行序号（可并发跑不撞名）
- **自动清理**：脚本末尾 SQL 批量删除测试数据（含历史遗留），`SET FOREIGN_KEY_CHECKS=0` 保证子表顺序无关
- **序列重同步**：清理后把各单据序列（PD/CGDD/XSDD/SH-XSDD/XSTH/TH/CPRK/PCTL/ST 等）重置为 `MAX(现存单号)`——**含软删行**，保证下一号 = MAX+1 永不复用（见 08-dev-notes.md 6.19 序列铁律）
- **测试数据名称带唯一后缀**：同一脚本可重复执行，不会因名称已存在而失败

## 已知边界

1. **备份恢复接口（POST /api/backup/restore）不测**：真实库恢复会回滚到备份时点，需在临时库验证（08-dev-notes.md 6.13）
2. **AI 接口依赖模型密钥**：无密钥时失败属环境依赖，非系统缺陷
3. **人为删除 sequences 行 + 并发首建**是极端场景：撞键是历史软删单据占位的数据问题，不是并发缺陷（已清理 2026-08-01 遗留的软删盘点单 PD-0003）
4. 报工打卡并发（同员工 10 并发）已修原子防重；序列并发用 UPDATE+INSERT+重试（踩坑记录见 6.19）
